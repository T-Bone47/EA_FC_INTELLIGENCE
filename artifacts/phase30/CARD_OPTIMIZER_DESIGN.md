# FC27 card assignment

A decision assigns one eligible item to one named formation slot. The search covers all submitted items, up to 50. V3.2 evaluates every submitted eligible item independently for each slot and tactic against the frozen UT_CARDS reference. The engine returns up to 50 contexts, so no eligible shortlisted result is truncated. Unit tests exercise the shared optimizer through its existing player entry point and through the new grouped entry point.

1. Reserve locked slots and their identity groups. A manually locked primary goalkeeper may fill a slot with a null score. Every other occupied slot must pass its positional and evidence gates.
2. Maximize the count of scored slots. At equal coverage maximize the sum of V3.2 scores at their native ten-decimal precision. When continuity is enabled, prefer the largest number of incumbents retained in their current slots. Break remaining ties by the lexicographically smallest tuple of item UUIDs in formation order, with empty slots represented by empty strings.
3. Process each identity group once in a bitmask dynamic program. A transition adds one edge to a previously unoccupied slot. The previous layer supplies all predecessors, so two variants from one confirmed footballer cannot both enter a path. After processing a group, the best path for a mask is sufficient because future groups have no dependence on which processed items were used. Bounded replacement search also keeps the edit count in the state.
4. Per slot, the top N distinct groups suffice for N slots. At most N−1 alternatives can be used elsewhere. Ranking by fit, continuity and item ID preserves the complete objective. Keep separate edit classes for constrained upgrades. Among groups confined to one slot, the best edge in each relevant edit class dominates the others.
5. Single and paired upgrades search the occupied, scored slots. Incumbent cards can stay where they are. Replacements must enter from outside the original roster. A formation transformation can reassign existing cards. Minimum-change mode selects the smallest number of replacements meeting the requested strictly positive improvement, then the highest fit at that count. Locked and unscored positions cannot generate a gain.

Confirmed base IDs come only from a RESOLVED review. Other eligible items are grouped by exact source-derived item UUID. Exploratory mode therefore cannot verify footballer uniqueness, even when item IDs differ. Conflicted observations are excluded in both modes. Strict mode requires a confirmed base ID.

The tactical matrix evaluates each generated lineup under every selected profile. Dominance compares scored count, then total fit within each tactic. Equal assignments are deduplicated for the frontier. The reported frontier covers the generated single-profile optima. Additional non-dominated compromises can exist elsewhere in the feasible set.
