# Open decisions

| Decision | Current engineering treatment |
| --- | --- |
| Release approvals and reviewer workflow | The registry decides eligibility. Migration 011 starts with an empty membership table. Data stewards must verify the source, release observation and exact canonical rows before activation. A change to a reviewed row or fact invalidates membership. |
| Tactical and calibration policy | Slot emphasis composes with existing tactical weights. The existing thresholds and golden artifacts still apply. A calibration owner must decide how to resolve the historical V3 statistical failures and legacy expectation conflicts. |
| Card rules and market rights | A data owner must verify version-specific role assignments, chemistry, market observations and Evolution rules before enabling those decisions. |
| Personalization training | The two editable preferences are statements. Feedback entity validation establishes visibility, while recommendation-origin receipts, evaluation labels, consent and training eligibility remain open. |
| Production activation | A named release owner must accept evidence from the actual deployed revision, including hosted CI and browser journeys. |
